# jev-bench

TypeSafe Jev와 Claude Haiku 5.5에 같은 한국어 고객 문의 티켓 20건을 보내고 토큰, 지연, 비용, 답 일치율을 비교한 벤치마크입니다.

## 결과 요약 (2026-10-13, Claude Haiku 5.5, 20건 모두 성공)

**같은 분류 작업에서 Jev가 약 6배 싸고 약 8배 빨랐고, 두 모델의 답은 90~95% 일치했습니다.**

| 모델 | 평균 입력 토큰 | 평균 출력 토큰 | 지연 p50 (ms) | 총비용 (USD, 20건) | 월 100만 건 환산 (USD) |
|---|---:|---:|---:|---:|---:|
| jev-latest | 482.1 | 73.0 | 190 | $0.000405 | $20.25 |
| claude-haiku-5-5 | 775.2 | 97.0 | 1455 | $0.002521 | $126.03 |
| Claude/Jev 배수 | 1.6x | 1.3x | 7.7x | 6.2x | 6.2x |

| 질문 | 일치율 | 기준 |
|---|---:|---|
| department (담당 부서) | 95% (19/20) | 라벨이 같으면 일치 |
| frustration (불만 정도) | 95% (19/20) | 단계(0/1/2)가 같으면 일치 |
| is_urgent (긴급 여부) | 90% (18/20) | 둘 다 0.5 이상이거나 둘 다 미만이면 일치 |

## 무엇을 물어봤나

### 판단 질문 3개 (두 모델 공통)

| 키 | 타입 | 질문 | 선택지 |
|---|---|---|---|
| department | choice | 어느 팀이 처리해야 하나? | billing(결제·환불·구독), technical(버그·장애·로그인·API·보안), sales(견적·신규 요금·데모·계약) |
| frustration | score | 고객이 얼마나 불만인가? | 0 차분 / 1 불만이지만 정중 / 2 매우 화남 |
| is_urgent | noul | 몇 시간 안에 대응해야 할 만큼 급한가? | 0~1 확률 |

## 토큰별 차이

### 입력 토큰: Claude가 티켓당 평균 293토큰 더 씀 (1.6배)

- Jev: 455~548토큰. 티켓 문장이 길수록 늘어납니다.
- Claude: 736~862토큰.
- 두 모델 모두 매 요청마다 질문 3개의 정의를 함께 보냅니다. Claude는 여기에 tool 정의(JSON 스키마)와 시스템 프롬프트가 붙고, tool을 쓸 때 API가 넣는 내부 지시문도 입력 토큰에 잡힙니다. 토크나이저가 서로 달라서 같은 한국어 문장도 토큰 수가 다르게 나옵니다.
- 입력 단가도 Claude가 2.4배 비쌉니다(0.10 vs 0.042 USD/MTok). 토큰 1.6배에 단가 2.4배가 곱해져, **입력 비용만 3.8배** 차이가 납니다.

### 출력 토큰: 개수는 비슷하지만 Jev 출력은 무료

- Jev: 모든 티켓에서 73토큰으로 고정. 출력 단가가 0이라 비용에 들어가지 않습니다.
- Claude: 모든 티켓에서 97토큰으로 고정. tool 호출 JSON(`{"department": ..., "frustration": ..., "is_urgent": ...}`)을 생성한 토큰이고, 0.50 USD/MTok로 과금됩니다.
- **Claude 비용의 38%가 출력**입니다. Jev는 이 부분이 0이라 비용 격차가 토큰 격차보다 커집니다.

### 월 100만 건 기준 비용 구성

| | 입력 | 출력 | 합계 |
|---|---:|---:|---:|
| Jev | $20.25 | $0 | $20.25 |
| Claude Haiku 5.5 | $77.52 | $48.50 | $126.03 |

## Jev가 강한 곳

1. **비용.** 입력이 더 적고 단가가 낮은 데다 출력이 무료라, 같은 판단을 6.2배 싸게 냈습니다. 하루 수만~수백만 건을 처리하는 백그라운드 분류에서 차이가 커집니다.
2. **지연과 안정성.** p50이 190ms(Claude 1455ms), 가장 느린 건도 254ms였습니다. Claude는 1203~4170ms로 편차가 컸습니다. 사용자가 기다리는 실시간 라우팅이나 화면 안의 판단에 유리합니다.
3. **확률과 확신도를 함께 반환.** 라벨만 주는 게 아니라 선택지별 확률을 줍니다. 그래서 "확신이 낮으면 사람에게 넘긴다" 같은 규칙을 코드로 바로 만들 수 있습니다. 실제로 아래 불일치 4건은 대부분 Jev 확률이 경계값 근처였습니다.
4. **출력 형식이 항상 맞음.** 미리 정한 선택지 안에서만 답해서 파싱 실패가 없습니다. Claude도 이번엔 20건 모두 형식을 지켰지만, 그건 tool 강제와 코드 검증을 넣었기 때문입니다.

**Jev가 맞지 않는 곳:** 답장 작성, 요약, 번역처럼 텍스트를 만들어야 하는 작업에는 쓸 수 없습니다. 선택지나 기준을 미리 정할 수 없는 열린 질문도 마찬가지입니다. 이번 결과는 **정형화된 분류·판정 작업에 한정된** 비교입니다.

## 해석할 때 주의할 점

- **일치율은 정확도가 아닙니다.** 정답 라벨을 따로 만들지 않았기 때문에, 두 모델이 서로 얼마나 같은 답을 냈는지만 보여줍니다.
- **표본이 작습니다.** 20건을 1회만 실행했습니다. 지연은 네트워크 상태에 따라 달라집니다.
- **Haiku 5.5 결과만 있습니다.** Sonnet·Opus 5.5는 강제 `tool_choice`를 지원하지 않아 조건이 달라지고(아래 "측정 방법" 참고), thinking 토큰까지 출력에 잡혀 차이가 더 벌어질 것으로 예상하지만 직접 돌려보지는 않았습니다.
- **단가는 직접 지정한 값입니다(USD/MTok, 입력/출력).** Jev 0.042/0, Haiku 0.10/0.50, Sonnet 2/10, Opus 4/20. 값은 `providers.py`의 `PRICES`에 있습니다.

## 측정 방법

- 질문 3개는 `data.py`에 한 번만 정의하고 두 모델에 똑같이 보냅니다.
  - `department`: choice (billing / technical / sales)
  - `frustration`: score 3단계 (차분 / 불만이지만 정중 / 매우 화남)
  - `is_urgent`: noul (긴급할 확률 0~1)
- Claude에는 같은 질문을 tool 하나의 `input_schema`로 바꿔 보냅니다. choice는 enum, score는 정수 범위, noul은 0~1 숫자입니다. Haiku 5.5는 `tool_choice`로 tool 호출을 강제합니다. Sonnet 5.5와 Opus 5.5는 강제 `tool_choice`를 400 오류로 거부하므로 `auto`와 effort `low`로 실행하고, tool 호출 없이 답하면 실패로 기록합니다.
- 토큰은 각 API 응답의 `usage` 값을 그대로 씁니다. 추정하지 않습니다. 지연은 HTTP 호출 한 번의 실제 경과 시간입니다.
- 호출은 한 건씩 순차로 하고 재시도는 하지 않습니다. 재시도하면 지연이 부풀고 실패가 가려지기 때문입니다.
- 건별 실패는 CSV에 기록하고 다음 건으로 넘어갑니다. 401/403이 나면 바로 중단합니다.
- 두 모델이 모두 성공한 티켓만 비교합니다.
- Jev의 `score`는 확률 가중 평균(예: 1.14)이라, 단계 비교에는 확률이 가장 높은 단계를 씁니다. 원래 값은 CSV의 `jev_frustration_raw`에 남깁니다.

## 실행 방법

```
pip install -r requirements.txt
```

키는 환경변수에서만 읽습니다. 둘 중 하나라도 비어 있으면 `run.py`는 아무것도 호출하지 않고 설정 방법만 출력합니다. **실제 키를 이 파일이나 코드에 적지 마세요.**

```powershell
$env:TYPESAFE_API_KEY = "..."
$env:ANTHROPIC_API_KEY = "..."
```

```
python test_run.py               # 오프라인 mock 테스트: 정상 / 500 / 401 경로
python run.py --limit 2          # 소량 실제 실행
python run.py                    # 20건 전체, Claude Haiku 5.5
python run.py --model sonnet     # 또는 opus
```

결과는 터미널에 마크다운 표로 나오고, 건별 상세는 `results.csv`(utf-8-sig, 엑셀에서 한글이 깨지지 않음)에 저장됩니다. `results.csv`는 `.gitignore`에 들어 있어 커밋되지 않습니다.
